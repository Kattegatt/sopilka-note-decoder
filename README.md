# Візуалізатор аплікатур хроматичної сопілки

Локальний desktop-first вебзастосунок для 10-отворної української хроматичної сопілки Мельнице-Подільського типу. Партитури обробляються в браузері. Без реєстрації ноти зберігаються тільки на пристрої; після входу й підтвердження email проєкти автоматично синхронізуються через ваш акаунт.

## Можливості

- введення ABC notation та імпорт `.abc`;
- імпорт MusicXML: `.musicxml`, `.xml`, `.mxl`;
- імпорт MIDI: `.mid`, `.midi`, вибір доріжки та голосу;
- строї C, D, F і G та два режими транспонування;
- українські назви нот і 10-отворні SVG-аплікатури;
- альтернативні аплікатури, конфлікти акордів і недоступні висоти;
- програвання з курсором і темпом 25–200%, метроном та локальна модель духового інструмента;
- локальне автозбереження, друк/PDF та PWA/offline;
- необов’язкова реєстрація через email і пароль та синхронізація нот між пристроями.

MIDI квантується до 1/32 ноти. Одночасні ноти імпортуються як акорди, а перекривні мелодичні лінії — як окремі голоси.

## Джерело аплікатур

Профіль сопрано C явно зіставляє ноти від До першої октави до Соль третьої октави з 49 схемами зі сторінки [Sopilka Acropolis](https://uk.sopilka-acropolis.com/fingering/fingerings-for-soprano-in-c/): 32 основні, 8 альтернативних і 9 квінтових. Зображення джерела не входять до застосунку — в коді збережені лише оцифровані стани 10 отворів.

## Запуск

Потрібен Node.js `>=22.13.0`.

```bash
npm install
npm run dev
```

Відкрийте [http://localhost:3000](http://localhost:3000). Команда запускає Vite та API на порту 3001; запити `/api` проксіюються через Vite. SQLite для розробки зберігається в `data/`.

Без SMTP листи для підтвердження пошти та відновлення пароля друкуються в терміналі API. Для локального SMTP можна передати змінні з `.env.example` через середовище процесу.

Після підтвердженого входу всі гостьові проєкти автоматично переносяться в акаунт. Зміни й видалення синхронізуються після локального збереження, повернення до вкладки та кожні 30 секунд. При конфліктах перемагає останній запис, прийнятий сервером: пізніше надіслані офлайн-зміни можуть замінити версію з іншого пристрою.

Локальні копії акаунта залишаються в IndexedDB після виходу, але не відображаються іншому акаунту. Це розділення в інтерфейсі, а не шифрування даних браузера. Офлайн-черга зберігається до наступного входу в той самий акаунт.

## Перевірка

```bash
npm test
npm run lint
npm run typecheck
npm run test:runtime
```

`npm run build` створює збірки фронтенда та API. `npm run start` запускає API; production запускається з `NODE_ENV=production` і змінними з `.env.example`. Браузерні сценарії запускаються через `npm run test:e2e` після встановлення Chromium для Playwright.

## Production

Production-застосунок працює на <https://sopilka.kattegatt.org/>. Push або merge
у `main` перевіряє код, публікує Docker image у GHCR та автоматично оновлює VPS.
Інструкції з експлуатації та відкату: [`docs/deployment.md`](docs/deployment.md).

Локальні конфіги AI-асистентів, приватні нотатки, промпти, плани та конфіг
ChatGPT Sites виключені через `.gitignore` і не потрібні для збірки.

## Звукові моделі

Застосунок використовує одну локальну модель духового інструмента. DSP заздалегідь скомпільований у WASM і не потребує мережі чи серверного аудіо. Ноти плануються через аудіогодинник Web Audio, а короткі плавні переходи рівня прибирають клацання під час зміни висоти. Вихідний DSP лежить у `dsp/`, а згенерований модуль — у `public/faust/`.
